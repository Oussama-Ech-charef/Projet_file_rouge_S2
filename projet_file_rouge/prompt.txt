## 4. DETAILED IMPLEMENTATION REQUIREMENTS

### A. Database & Migrations
1. **`databases/sql/database.sql`**:
   - Creates database `cabinet_medical` with `utf8mb4`.
   - Tables: `patient`, `specialite`, `consultation`, `ordonnance`.
   - Table `specialite` MUST include the column: `image VARCHAR(255) NOT NULL`.
   - Foreign key constraints with proper `ON DELETE` / `ON UPDATE` cascades.
   - Seed data:
     - 6 Specialties with exact descriptions and relative image paths pointing to `assets/images/`:
       1. Cardiologie -> `assets/images/Cardiologie.jpe`
       2. Dermatologie -> `assets/images/Dermatologie.jpe`
       3. Pédiatrie -> `assets/images/Pédiatrie.jpe`
       4. Gynécologie -> `assets/images/Gynécologie.jpe`
       5. Ophtalmologie -> `assets/images/Ophtalmologie.jpe`
       6. Médecine générale -> `assets/images/Medecine_generale.jpe`
     - Realistic sample records for `patient`, `consultation`, and `ordonnance`.
2. **`databases/migrations/001_add_image_to_specialite.sql`**:
   - `ALTER TABLE specialite ADD COLUMN image VARCHAR(255) NOT NULL DEFAULT '' AFTER description;`
   - `UPDATE` statements setting the real image path for each of the 6 specialties.

### B. Database Documentation (4-Way Absolute Consistency)
Ensure 100% strict alignment across these 4 files:
1. **`dictionnaire_donnees.csv`**:
   - Header must be EXACTLY: `Interface,Name,Signification,Type,Obligatoire,Calculé`
   - Fully document all fields of `Patient`, `Spécialité` (including `image`), `Consultation`, and `Ordonnance`.
2. **`dependances_fonctionnelles.md`**:
   - Document in format: `Identifier → Attributes of the same entity`.
   - Include `specialite.id → specialite.image`.
3. **`identifiants.md`**:
   - Clearly document the Primary Key (PK) for each entity (`id INT AUTO_INCREMENT PRIMARY KEY`).
4. **`databases/sql/database.sql`**:
   - Matches the documentation identically in column names, types, nullability, and keys.

### C. PDO Connection (`config/database.php`)
- Centralized reusable connection with DSN `mysql:host=127.0.0.1;dbname=cabinet_medical;charset=utf8mb4`.
- Mandatory `try / catch (PDOException $e)`.
- Enable `PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION` and `PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC`.
- Implement graceful error handling: if MySQL is offline or not configured yet, do not crash with a fatal error; capture `$pdo_error` and enable fallback presentation where applicable.

### D. Public Home Page (`pages/home.php`)
- Modern, clean, healthcare aesthetic (not outdated or generic).
- **Header**: Includes `includes/header.php` (Logo, Navigation links, Login button — **NO Dashboard link**).
- **Hero Section**:
  - High visual impact, spacious typography, badge, title, subtitle, CTA buttons.
  - Displays the provided hero image: `../assets/images/hero.jpe`.
- **Search & Filter**:
  - Live search input + dropdown filter for the medical specialties.
  - Interactive via `assets/js/main.js` (vanilla JS, instant DOM filtering).
- **6 Specialty Cards**:
  - Rendered dynamically from the database via PDO (`SELECT id, nom, description, image FROM specialite`).
  - Image paths are read directly from the `specialite.image` column in MySQL.
  - Fallback data array ensures cards still display if DB is momentarily unreachable.

### E. Login Page (`pages/login.php`)
- Clean, focused card centered in a professional layout.
- Inputs: Email and Password.
- Submit button directly navigates to `dashboard.php` (even with empty inputs, respecting the UI prototype rule).

### F. Dashboard (`pages/dashboard.php`)
- Two-column layout with reusable `includes/sidebar.php` and main content area.
- Sidebar switches entities via query parameter: `?entity=patients`, `consultations`, `specialites`, `ordonnances`.
- Each entity displays:
  - Header with title and "+ Ajouter" button.
  - Complete data table listing all records with formatted columns.
  - Table action links for every row: **View** (`view.php`), **Edit** (`dashboard.php?action=edit&id=...`), **Delete** (`actions/delete.php?entity=...&id=...`).
- Inline modal/panel forms for "Add" and "Edit" prefilled with existing data.

### G. Server Actions (`actions/add.php`, `actions/edit.php`, `actions/delete.php`)
- Processing logic separated from presentation.
- Secure prepared statements (`$stmt = $pdo->prepare(...)`).
- Proper POST validation.
- Redirect back to `pages/dashboard.php?entity=...&msg=...` with clear success or error messages.

### H. Detail View (`pages/view.php`)
- Reusable detail card for viewing a single record for any of the 4 entities.
- Loads data directly from MySQL using PDO prepared statement by ID.
- Displays full attributes in a clean grid. For `specialite`, displays the associated image. For `consultation` and `ordonnance`, performs `LEFT JOIN` to display patient and specialty names.
- Displays a clear `Record not found.` card if the record does not exist.
- Includes a direct "Retour à la table" button.

### I. Styling (`assets/css/style.css`)
- Professional medical palette: clinical blues (`#0284c7`, `#0369a1`), soft teal accents (`#0d9488`), clean neutrals, subtle borders (`#e2e8f0`), soft modern box-shadows.
- CSS custom properties (variables) for consistent colors, typography, border-radii, and transitions.
- Fully responsive across desktop, tablet, and mobile screens.
